## 一、产品概述

### 1.1 背景与问题

多数人清楚自己"挣多少"，但说不清"钱花哪了"。现有记账工具存在两类问题：

1. **记账太麻烦**：步骤多、启动慢，坚持不过三天；每天记录消费这件事，门槛必须足够低。
2. **记了没反馈**：只有流水没有分析，看不到"钱去哪了""哪里花多了"，感受不到记账的价值。

### 1.2 产品定位

一款面向个人的**轻量级记账工具**，核心主张：

> **10 秒记完一笔，月底一眼看清钱去哪了。**

- 轻输入：最快路径记账，减少每一次点击。
- 重反馈：自动汇总、图表化分析、预算预警，让"记账"换来"看得见的回报"。

### 1.3 目标用户

- 有记账意识但难以坚持的年轻人（学生、初入职场者）。
- 想控制月度开销、有储蓄目标的人。
- 核心是**单人使用**，V1 不涉及多人协作。

### 1.4 产品目标与衡量指标

| 目标 | 衡量指标 |
| --- | --- |
| 记账足够快 | 单笔记账操作 ≤ 10 秒；记账页首屏打开 ≤ 300ms |
| 用户能坚持 | 连续记账 ≥ 7 天的用户占比 |
| 有使用粘性 | 周平均记账天数 ≥ 5 天 |
| 能看懂消费 | 用户每周至少打开 1 次统计页 |

## 二、用户画像与核心场景

### 2.1 用户画像

**画像 A：小林，24 岁，职场新人**
- 月工资到手后想攒钱，但月底总是"不知不觉花完"。
- 诉求：知道钱花在哪几个类别，给自己定个每月额度，超了要提醒。

**画像 B：阿哲，30 岁，理性消费者**
- 已有记账习惯，但嫌现有工具繁琐，只想快速记一笔、月底看汇总。
- 诉求：记账速度要快，报表要一眼看懂，数据能导出自己留档。

### 2.2 核心使用场景

| 场景 | 描述 | 对应功能 |
| --- | --- | --- |
| 早餐买完单 | 排队出门的 10 秒内记下"早餐 12 元" | 快速记一笔 |
| 吃完晚饭回想今天 | 打开小管家补记几笔，看看今天花了多少 | 账单明细（按日分组） |
| 月中看进度 | 本月已花多少？预算还剩多少？日均还能花多少？ | 统计报表 + 预算 |
| 月底复盘 | 这个月哪类花销最多？比上月多还是少？ | 分类占比 + 月度对比 |
| 换手机/留档 | 把所有账单导出成文件保存 | 数据导出 |

## 三、需求范围

### 3.1 优先级总览

**P0（V1.0 MVP，必须做）**

1. 记一笔账（支出/收入）
2. 账单明细（浏览 / 筛选 / 编辑 / 删除）
3. 分类管理（默认分类 + 自定义）
4. 统计报表（月度总览、分类占比、趋势、月度对比）
5. 月度预算与超支提醒
6. 数据导出（CSV）
7. 本机账户注册登录（V1.0.1 增补，见 4.7）
8. 供应商管理（V1.0.2 增补，见 4.8）
9. 记账图片上传（V1.0.2 增补：最多 5 张、自动压缩，见 4.9）

**P1（V1.1，值得做）**

1. 周期记账（房租、订阅等固定收支自动入账）
2. 快捷模板（一键记常用账单，如"地铁 4 元"）
3. 多账本（如"日常""旅行"分开记）
4. 连续记账打卡与提醒（习惯养成）
5. 桌面小组件 / 通知栏快捷记账（依赖移动 App 端，随多端迭代实现）

**P2（V2.0，远期）**

1. 多端同步（云端备份）
2. 票据拍照识别（OCR）记账、语音记账
3. 家庭/情侣共享账本
4. AI 月度分析报告（消费建议）

### 3.2 明确不做（V1 范围外）

- **不接入微信/支付宝/银行账单自动同步**：涉及账号授权与合规成本，且与"轻量"定位冲突。
- **不做投资理财、资产净值管理**：聚焦"日常收支"这一个核心场景。
- **不做社交、社区功能**。

## 四、功能需求详述（P0）

### 4.1 记一笔账（核心功能）

**功能描述**：用户在 10 秒内完成一笔收支记录。

**字段说明**

| 字段 | 必填 | 默认值 | 规则 |
| --- | --- | --- | --- |
| 类型 | 是 | 支出 | 支出 / 收入切换，切换后联动分类列表 |
| 金额 | 是 | 空 | 数字键盘输入；> 0；最多两位小数；上限 99,999,999 |
| 分类 | 是 | 按类型取上一次使用的分类 | 单选，见 4.3 分类体系 |
| 账户/支付方式 | 否 | 现金 | 现金 / 微信 / 支付宝 / 银行卡 / 信用卡，可自定义 |
| 日期 | 是 | 今天 | 可改为过去日期（补记）；不可选未来日期 |
| 供应商 | 否 | 空 | 可选；输入框带自动补全建议；新名称保存时自动创建（V1.0.2） |
| 备注 | 否 | 空 | ≤ 50 字 |

**交互规则**

1. 保存成功后自动关闭记账页，在明细列表顶部出现该笔记录（轻提示，1.5s 后消失）。
2. 金额为空或为 0 时，保存按钮置灰。
3. 支持从记账页直接"再记一笔"（保存后不退出，金额清空）。

**验收标准**

- [ ] 正常填写必填项后可保存成功，明细列表立即可见。
- [ ] 金额非法（空/0/超过上限/超过两位小数）时无法保存并给出提示。
- [ ] 切换支出/收入后，分类列表正确联动。

### 4.2 账单明细

**功能描述**：按时间倒序查看所有账单，支持筛选与管理。

**交互规则**

1. 按日分组展示，每组头部显示当日小计（支出红 / 收入绿）。
2. 页面顶部显示当月汇总：本月支出、本月收入、本月结余；有图片附件的账单显示 📷 标记（V1.0.2）。
3. 筛选维度：时间范围（本月/上月/自定义区间）、类型（支出/收入）、分类、账户、供应商（V1.0.2）、备注关键词。
4. 点击账单进入编辑；删除需二次确认（弹窗），删除为**软删除**，可在回收站恢复（保留 30 天）。
5. 下拉刷新、触底加载更多（分页）。

**验收标准**

- [ ] 各筛选维度可独立或组合使用，结果正确。
- [ ] 编辑后列表与统计同步更新。
- [ ] 删除后记录从列表消失，回收站内可见且可恢复。

### 4.3 分类管理

**默认分类（预置，可改名、可停用、不可删除）**

- 支出：餐饮、交通、购物、居住、娱乐、医疗、教育、人情往来、其他
- 收入：工资、兼职、理财收益、红包礼金、其他

**交互规则**

1. 支持新增自定义分类（名称 + 图标 + 归属类型）。
2. 支持**排序**（长按拖拽），常用分类排前面，降低记账成本。
3. 分类"停用"后不再出现在记账选择中，但历史账单仍正常展示（**不做物理删除**，避免历史数据分类丢失）。
4. 已有账单的分类改名后，历史账单同步显示新名称。

**验收标准**

- [ ] 新增/改名/排序/停用即时生效。
- [ ] 停用的分类无法再被选中，但历史账单展示不受影响。

### 4.4 统计报表

**功能描述**：把流水变成可读的消费洞察。

**内容结构（月维度为默认）**

1. **月度总览卡**：本月支出 / 收入 / 结余，以及与上月的增减百分比。
2. **分类占比**：支出按分类从高到低排列（条形图 + 百分比），点击可跳转到该分类的账单明细。
3. **每日趋势**：当月每日支出柱状图，周末/大额日高亮。
4. **月度对比**：近 6 个月支出折线图。
5. **供应商排行**：当月支出 Top5 供应商（条形列表，V1.0.2），点击跳转到按该供应商筛选的明细。
6. 支持切换月份（左右滑动或月份选择器）。

**验收标准**

- [ ] 图表数据与明细账单汇总一致（同一口径，含已删除账单剔除）。
- [ ] 点击分类占比可跳转到对应筛选结果。

### 4.5 预算管理

**功能描述**：设定每月支出预算，实时反馈进度，超支提前预警。

**交互规则**

1. V1 仅支持**月度总预算**（分类预算放到 V1.1）。
2. 预算页展示：本月预算、已使用、剩余金额、本月已过天数、**日均可用** =（预算 − 已使用）÷ 剩余天数。
3. 预警规则：已使用达预算 **80%** 时提醒一次（"预算快用完啦"）；**100%** 时再提醒一次。V1（H5）以页面内提示为主：打开时弹提示 + 预算页红点；推送提醒随后续移动 App 端补齐。
4. 未设置预算时展示引导设置入口。
5. 预算按自然月计算，每月 1 日重置。

**验收标准**

- [ ] 日均可用的计算在跨月、月中修改预算等情况下正确。
- [ ] 80% / 100% 两个阈值各触发一次提醒，不重复骚扰。

### 4.6 数据导出与备份

1. 支持将全部账单导出为 **CSV 文件**（UTF-8，含 BOM，保证 Excel 打开中文不乱码）。
2. 字段：日期、类型、分类、供应商（V1.0.2 新增）、账户、金额、备注；图片附件不随 CSV 导出。
3. V1 数据仅存本地，导出是用户唯一的外部备份方式；后续版本再考虑云端备份。

**验收标准**

- [ ] 导出文件可在 Excel 中正确打开且中文显示正常。
- [ ] 导出数据与小管家内账单一一对应。

### 4.7 注册登录（V1.0.1 增补：本机账户锁）

**定位说明**：应需求方要求增加注册登录。V1 无服务端、数据不上传，因此本版本的「注册登录」定位为**本机账户锁**——一个本机主人账户，密码用于锁定账单隐私；真正的云端账号体系（找回密码、多端登录、数据同步）随 V2.0 云同步实现。

**字段规则**

| 字段 | 必填 | 规则 |
| --- | --- | --- |
| 用户名 | 是 | 2–16 位字符，注册后不可修改（V1.0.1） |
| 密码 | 是 | ≥ 6 位；以「随机盐 + SHA-256 多轮迭代」哈希存储，不存明文 |
| 确认密码 | 是（注册） | 与密码一致 |
| 免登录 | 否 | 勾选后 7 天内免输密码；不勾选则本次浏览器会话内有效 |

**交互规则**

1. 首次启动（本机无账户）→ 全屏注册页；注册成功即登录进入应用。
2. 已有账户时启动 → 全屏登录页；用户名 + 密码校验通过后进入。
3. 连续输错 5 次密码 → 锁定 5 分钟，期间无法尝试。
4. 「我的」页展示当前账户，可退出登录；退出后立即回到登录页。
5. 数据按账户命名空间隔离存储；V1.0 已产生的本机旧数据在登录后自动继承，不丢失。

**明确不做（V1.0.1）**：云端注册与登录、找回密码（本机无服务端，遗忘密码 = 数据无法访问，注册页必须醒目提示）、多账户切换、修改密码（列入 V1.1）。

**验收标准**

- [ ] 无账户时先注册才能进入；注册后下次打开需登录。
- [ ] 密码错误无法进入；连错 5 次锁定 5 分钟。
- [ ] 勾选「7 天免登录」后 7 天内打开直接进入；退出登录后立即回到登录页。
- [ ] 升级前记录的账单在注册/登录后完整保留。
- [ ] 注册页明示「忘记密码将无法找回」。

**V2.0 云端化增补（2026-10-28）**：随架构迁移至 Cloudflare，「本机账户锁」升级为**云端账户体系**，交互规则与验收标准中「本机」语义替换如下：

1. 账户存于服务端数据库（D1），同一部署下可注册多个账户，数据一律按 user_id 隔离，跨账户互不可见。
2. 密码改为「随机盐 + PBKDF2-SHA256（Web Crypto，10 万次迭代）」服务端哈希存储；会话为服务端签发的 HttpOnly + Secure Cookie（KV 存会话令牌）。
3. 免登录 / 连错 5 次锁 5 分钟 / 退出登录规则不变；「连错锁定」由服务端按账户计数（KV）。
4. 旧 V1 版本的本地数据不做自动迁移：新云端版从空账开始，旧数据由用户在旧版导出 CSV 自行留存。
5. 忘记密码仍无法找回（本阶段不做找回密码，注册页保留醒目提示）。

### 4.8 供应商管理（V1.0.2 增补）

**定位**：供应商即消费的"商户/场所"（如：楼下早餐店、美团、京东、全家便利店），回答"钱花在哪家"。**可选字段**，不进入记账默认路径，不影响"10 秒记账"。

**数据规则**：供应商含 id、名称（≤12 字，同名校验）、状态（启用/停用）、排序、创建时间。V1.0.2 预置空列表，全部由用户产生；记账页输入新名称保存时自动创建（自定义）。

**交互规则**

1. 「我的 → 供应商管理」：添加 / 重命名 / 停用 / 启用 / 排序。
2. 停用的供应商不再出现在记账建议中，历史账单展示不受影响（不做物理删除）。
3. 记账页供应商为可选输入：带已启用供应商的自动补全建议；输入新名称保存时自动创建。
4. 明细筛选新增"供应商"维度；统计页新增"供应商排行"（当月支出 Top5，点击跳转对应筛选明细）。

**验收标准**

- [ ] 记账页可直接输入并保存新供应商，管理页同步出现。
- [ ] 停用的供应商不再出现在建议与筛选新建项中，历史账单不受影响。
- [ ] 供应商排行数据与明细一致（剔除已删除账单）。

### 4.9 记账图片上传（V1.0.2 增补）

**需求**：记账时可上传照片（小票、商品图等）作为凭证，每笔最多 5 张，图片必须压缩后存储以节约空间。

**规则**

1. 记账/编辑页提供图片附件区，最多 5 张（显示 n/5 计数）；支持 JPEG/PNG/WebP，单张原图 ≤ 20MB。
2. 压缩策略：最长边 ≤ 1280px，统一转 JPEG（初始质量约 0.72）；若仍超限则逐级降低质量、再缩小尺寸，目标单张存储 ≤ 约 200KB；处理失败（格式不支持等）跳过该图并提示。
3. 存储：图片与账单主体**分开存储**（V2.0 起：二进制入 R2 对象存储、D1 仅存元数据与索引，按 user_id 隔离；V1.0.2 为 localStorage dataURL），避免大图拖慢账单列表；软删除时保留（恢复可见），彻底删除时一并清除。
4. 明细列表中带图账单显示 📷 标记；编辑页点缩略图全屏预览，点击关闭。
5. CSV 导出不含图片；图片访问需登录鉴权（服务端流式代理返回）。

**验收标准**

- [ ] 最多上传 5 张，第 6 张被拒绝并提示。
- [ ] 3MB 以上原图压缩后存储 ≤ 约 200KB，且预览清晰（最长边 1280px）。
- [ ] 编辑换图/删图保存后即时生效；彻底删除账单后其图片同步清除。
- [ ] 软删除 → 恢复后图片仍在。

## 五、信息架构与页面结构

### 5.1 页面树（V1，底部 4 个 Tab）

```
小管家（V1：H5 Web/PWA）
├── 本机账户锁（V1.0.1：未登录时全屏锁定——注册 / 登录 / 7 天免登录 / 退出）
├── Tab1 明细（首页）
│   ├── 当月汇总卡（支出/收入/结余）
│   ├── 按日分组账单列表
│   ├── 筛选入口 → 筛选面板
│   ├── 账单编辑页
│   └── 悬浮按钮：记一笔

│   ├── 月度总览卡

    ├── 分类管理

    ├── 账户管理
    ├── 数据导出 / 回收站
    └── 设置（关于等）
```

### 5.2 核心流程：记一笔账

```
打开小管家（或点悬浮按钮）
→ 记账页（默认支出、金额为空、分类为上次使用、日期今天）
→ 输入金额 →（可选）换分类/账户/供应商/日期/备注，附图片（≤5 张，自动压缩）
→ 点保存
→ 回到明细页，顶部轻提示"已记录"，当月汇总卡与今日列表即时更新
```

设计原则：**默认值兜底一切**——除了金额，其他字段都可以不碰，这是"10 秒记账"的保障。

## 六、数据模型（概念层）

> 金额一律以"分"为单位存整数，避免浮点误差；账单使用软删除。

**transaction（账单）**

| 字段 | 类型 | 说明 |
| --- | --- | --- |
| id | string | 主键 |
| type | enum | expense / income |
| amount | int | 金额（分） |
| category_id | string | 分类，外键 |
| supplier_id | string | 供应商，外键，可空（V1.0.2） |
| account_id | string | 账户/支付方式，外键 |
| date | date | 所属日期（统计按此归月） |
| note | string | 备注，可空 |
| created_at / updated_at | datetime | — |
| deleted_at | datetime | 软删除标记，空 = 正常 |

**category（分类）**：id、name、type（expense/income）、icon、sort、status（启用/停用）、is_default

**account（账户）**：id、name、type（cash/wechat/alipay/bank/credit）、sort

**supplier（供应商）**：id、name（≤12 字）、status（启用/停用）、sort、created_at（V1.0.2）

**budget（预算）**：id、month（yyyy-MM）、amount（分）、updated_at

**photos（图片附件）**：与账单主体分开存储——V1.0.2 为按账单 id 索引的 DataURL 数组（每笔 ≤5 张）；V2.0 起二进制存 R2（key：`photos/<user_id>/<transaction_id>/<sort>.jpg`），D1 仅存元数据（id、user_id、transaction_id、r2_key、size、sort）

**V2.0 云端存储介质（2026-10-28）**

| 介质 | 用途 |
| --- | --- |
| Cloudflare D1 (SQLite) + Drizzle ORM | users / categories / accounts / suppliers / transactions / budgets / photos 全部结构化数据；金额一律「分」整数、账单软删除 deleted_at |
| Cloudflare R2 | 图片二进制（按 user_id 隔离），读取经服务端鉴权后流式返回 |
| Cloudflare KV | 会话令牌（TTL 即会话期）、登录失败计数与锁定、用户偏好（lastCategory）与预算提醒触发标记 |

## 七、非功能需求

| 维度 | 要求 |
| --- | --- |
| 性能 | 记账页首屏 ≤ 300ms；千条流水下列表滚动与筛选不卡顿 |
| 离线 | V1 全部功能离线可用（无服务端依赖）；V2.0 起改为在线优先——Service Worker 仅缓存静态资源（壳/图标/样式），数据与 API 一律实时访问云端 |
| 隐私安全 | V1 数据仅存本地；V2.0 起账单数据存云端 D1/R2，按 user_id 隔离，传输全程 HTTPS，会话为 HttpOnly + Secure Cookie，密码 PBKDF2 加盐哈希；导出需用户主动触发；删除均有确认或可恢复机制 |
| 数据准确性 | 金额整数存储；统计口径唯一（按账单 date 归月，剔除已删除），服务端（services/stats）与客户端使用同一口径 |
| 兼容性 | H5（Web/PWA）：移动端浏览器优先（iOS Safari / Android Chrome），桌面浏览器可用；支持添加到主屏幕（PWA 安装） |
| 可扩展 | 分类、账户、账本（后续）在数据层解耦，为多账本及多端（App、小程序）预留结构；服务端逻辑按 services 分层，UI 组件与数据操作解耦 |

## 九、风险与开放问题

| # | 问题 | 说明 | 建议 |
| --- | --- | --- | --- |
| 1 | 记账动力如何持续 | 工具再快，不打开就没数据 | V1.1 的打卡提醒是关键，MVP 阶段先验证体验流畅度 |
| 2 | 是否需要二级分类 | 增加维护成本，违背"轻"定位 | V1 不做，观察真实数据后再定 |
| 3 | 多币种 | 出境消费场景 | V1 不做，记账时统一按本位币记录 |
| 4 | 预警触达方式 | PWA 推送在部分平台/浏览器受限 | V1 以页面内红点 + 打开时提示兜底；推送随移动 App 端补齐 |
| 5 | H5 本地存储可靠性 | 浏览器清理缓存/隐私模式可能清空本地数据 | 引导用户定期 CSV 导出；尽早申请持久化存储；云同步在 V2.0 优先排期 |

## 十、评审决议（2026-10-26，已全部确认）

1. **产品名称：小管家**。
2. **端形态：V1 只做 H5 网页端（Web/PWA）**，移动端浏览器优先；移动 App、小程序在后续版本迭代实现。
3. 默认分类维持现方案（9 支出 + 5 收入），不做调整。
4. V1 不做分类预算，仅月度总预算。
5. 回收站保留期 30 天。
6. **V1.0.1（2026-10-27 增补）：增加注册登录**——定位为本机账户锁（隐私保护）：单本机账户、密码加盐哈希、7 天免登录、连错 5 次锁定 5 分钟；云端注册/找回密码/多账户随 V2.0 云同步实现。遗忘密码无法找回，注册页须明示。
7. **V1.0.2（2026-10-27 增补）**：新增供应商管理（可选字段、记账自动创建、统计 Top5 排行）与记账图片上传（每笔 ≤5 张，最长边 1280px、目标单张 ≤200KB，与账单主体分开存储）；CSV 增加供应商列、不导出图片。
